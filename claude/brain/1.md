## Структура ТЗ
Файл: `/home/rizo/sai/ТЗ/sai_0_0_2.md`

Документ включает 13 разделов:
1. Описание продукта
2. Целевая аудитория и позиционирование (с таблицей сегментов)
3. Технологический стек (с обоснованием отказа от альтернатив)
4. Архитектура приложения (layer diagram ASCII + data flow)
5. Структура данных (tree.json, Node, Edge, chat format)
6. Функциональные требования (таблица с ID, приоритетом, стадией)
7. Нефункциональные требования (производительность, безопасность, совместимость)
8. Требования к UI/UX (layout ASCII, QSS-стили, визуал узлов)
9. Детальная спецификация модулей (API каждого модуля с сигнатурами)
10. Структура проекта (файловая структура)
11. Этапы разработки MVP (8 стадий с чек-листами)
12. Приложение A: Референсы
13. Приложение B: Глоссарий

## Выводы и уроки

1. **Write не работает для несуществующих файлов** — нужно сначала создать файл через Bash (touch/cat), потом использовать Edit/Write. В данном случае cat > file сработал.
2. **Исходное ТЗ в sh_2.md продублировано трижды** — это нормально для накопительного обсуждения, но при синтезе нужно было дедуплицировать.
3. **При создании ТЗ важно указывать версию** — пользователь явно указал `sai_0_0_2.md`, что подразумевает версионность документа.
4. **Полезно добавлять таблицы с ID требований** — это упрощает трекинг при разработке.
5. **sh_2.md содержал сильные аналитические инсайты про роли (BSA/PM/TL) — их стоит переиспользовать при позиционировании продукта.**
