## 1. Цель версии 0.0.5

Версия `0.0.5` превращает текущий прототип в управляемый продуктовый цикл:

- пользователь работает сразу с тремя деревьями;
- синхронизация выполняется осознанно и подтверждаемо;
- между деревьями появляются явные мосты-связи;
- ИИ-чат может менять узлы не только генерировать идеи;
- экспорт становится пользовательским (PDF/MD/PNG, с выбором формата);
- в проект добавляются шаблоны, контроль сохранения, управление провайдерами и расходом токенов.

Главная задача версии: **закрыть пробел в бизнес-логике и обеспечить предсказуемую разработку продукта через Sai**.

## 2. Продуктовые решения, зафиксированные бизнес-логикой

### 2.1. Проекты и сохранение

- Вложенные проекты не поддерживаются.
- Экспорт/импорт проектов обязателен.
- Автосохранение переключаемое в `Settings`.
- При выходе с несохраненными изменениями показывается подтверждение.
- Отдельная кнопка отката к бэкапу не нужна, базовый откат через `Undo/Redo`.

### 2.2. Три дерева и синхронизация

- Режим синхронизации: сразу для всех трех деревьев.
- Каскадное влияние: ИИ предлагает изменения в смежных деревьях, пользователь подтверждает.
- Меж-деревья связи обязательны как отдельный визуальный тип сущности (мосты).

### 2.3. Чат и контекст

- Ручное прикрепление узлов в чат разрешено.
- Память узловых чатов остается изолированной.
- Глобальный чат может **мутировать существующие узлы** (создавать/редактировать/связывать), а не только генерировать.
- Срок хранения сообщений: 30 дней по умолчанию, настраиваемо.

### 2.4. Экспорт

- Форматы: `PDF`, `Markdown`, `PNG`.
- Пользователь выбирает формат в UI.
- Статический HTML в этой версии не реализуется.

### 2.5. ИИ-провайдеры

- Поддержка нескольких API-ключей.
- Быстрый переключатель провайдера/модели прямо в панели чата.
- Отображение расхода токенов/стоимости обязательно (минимальный уровень).

### 2.6. Рабочий процесс

- Статусы узлов остаются гибкими (без принудительного автомата переходов).
- Поддержка шаблонов проектов обязательна.
- Метрики минимальные: количество узлов + базовое распределение.

## 3. Функциональные требования

### 3.1. Проекты, сохранение и безопасный выход

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-001 | Включение/выключение автосохранения в `Settings` | MUST |
| F-002 | При выходе с `dirty state` показывать диалог: Сохранить / Не сохранять / Отмена | MUST |
| F-003 | Экспорт проекта в отдельный файл | MUST |
| F-004 | Импорт проекта из файла | MUST |

### 3.2. Три дерева и меж-деревья мосты

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-010 | Единая синхронизация сразу трех деревьев по кнопке | MUST |
| F-011 | Экран подтверждения каскадных изменений перед применением | MUST |
| F-012 | Новый тип связи `cross-tree edge` (мост между деревьями) | MUST |
| F-013 | Визуальный элемент моста отображается на холсте как отдельный объект | MUST |
| F-014 | Переход по мосту фокусирует целевой узел в другом дереве | SHOULD |

### 3.3. Чат: контекст и мутации

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-020 | Узловой чат: контекст изолирован в рамках выбранного узла | MUST |
| F-021 | Ручное прикрепление дополнительных узлов в чат | MUST |
| F-022 | Глобальный чат может создавать/изменять/удалять узлы | MUST |
| F-023 | Все мутации из чата проходят через подтверждение пользователя | MUST |
| F-024 | История чатов хранится 30 дней по умолчанию | MUST |
| F-025 | Параметр срока хранения настраивается в `Settings` | SHOULD |

### 3.4. Экспорт и шаблоны

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-030 | Диалог экспорта с выбором формата `PDF / Markdown / PNG` | MUST |
| F-031 | Экспорт выбранного дерева или всех деревьев | MUST |
| F-032 | Создание шаблона из текущего проекта | MUST |
| F-033 | Создание проекта из шаблона | MUST |
| F-034 | Управление шаблонами (переименование/удаление) | SHOULD |

### 3.5. Провайдеры ИИ и стоимость

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-040 | Хранение нескольких API-ключей по провайдерам | MUST |
| F-041 | Быстрый переключатель провайдера/модели в UI чата | MUST |
| F-042 | Отображение токенов на ответ/сессию | MUST |
| F-043 | Отображение ориентировочной стоимости (если есть тарифные данные) | SHOULD |

### 3.6. Метрики и рабочий контроль

| ID | Требование | Приоритет |
|----|-----------|-----------|

## 4. Нефункциональные требования

| ID | Требование |
|----|-----------|
| N-001 | UI остается отзывчивым при активной работе с графом и чатом |
| N-002 | Все потенциально долгие операции выполняются асинхронно |
| N-003 | Логи ошибок хранятся локально до 96 часов |
| N-004 | Ошибки ИИ и экспорта отображаются понятным диалогом без краша |
| N-005 | Формат проекта обратно совместим минимум с `v0.0.4` (через миграции) |
| N-006 | Состояние после перезапуска соответствует последнему подтвержденному сохранению |
| N-007 | Код модулей бизнес-логики и UI должен быть разделен (без смешения ответственности) |

## 5. Требования к UI/UX

### 5.1. Основная композиция экрана

- Центральная область: холст деревьев.
- Правая панель: ИИ-чат с быстрым свитчером провайдера.
- Снизу: миникарта.
- Слева: окно структуры/навигации (по текущему UI-контексту приложения).

### 5.2. Синхронизация и каскад

- Кнопка `Синхронизировать 3 дерева`.
- После анализа: модальное окно с предложениями изменений.
- Для каждого изменения: принять/отклонить.
- После подтверждения: единый commit изменений + возможность `Undo`.

### 5.3. Мосты между деревьями

- Мост рендерится визуально отличимым от обычной связи.
- У моста есть метка источника/цели (`из какого дерева -> в какое`).
- Клик по мосту показывает карточку связи; двойной клик переводит к целевому узлу.

### 5.4. Чат

- В чат-панели отображается активный провайдер/модель.
- Рядом селектор для быстрого переключения.
- Каждое сообщение ассистента, содержащее мутацию графа, имеет блок:
  - предпросмотр изменений,
  - кнопки `Применить` / `Отклонить`.

### 5.5. Экспорт и шаблоны

- `ExportDialog` с явным выбором формата.
- `TemplateDialog` с действиями:
  - Сохранить как шаблон,
  - Создать из шаблона,
  - Удалить шаблон.

## 6. Изменения в модели данных и хранении

### 6.1. Новые/обновленные сущности

```python
Project
- id
- name
- trees: [functional, development, business]
- settings
- templates_ref

CrossTreeEdge
- id
- source_tree
- source_node_id
- target_tree
- target_node_id
- label
- meta

ChatSession
- id
- scope: node | global
- node_id (optional)
- provider
- model
- created_at
- expires_at
```

### 6.2. Настройки проекта

```python
settings = {
  "autosave_enabled": true,
  "chat_retention_days": 30,
  "default_export_format": "markdown",
  "ai_provider": {
    "active_provider": "openrouter",
    "active_model": "..."
  }
}
```

### 6.3. Совместимость

- Требуется версия схемы данных (`schema_version`) в проектном файле.
- При загрузке старого формата вызывается мигратор:
  - добавление полей настроек по умолчанию;
  - нормализация новых типов связей.

## 7. Технические изменения по модулям

### 7.1. Core / Business Layer

- Добавить `SyncService` для пакетной синхронизации трех деревьев.
- Добавить `CrossTreeService` для управления мостами.
- Добавить `TemplateService` (save/load/delete/list).
- Добавить `ChatMutationService` для проверки и применения предложений ИИ.
- Добавить `MetricsService` (агрегация базовых счетчиков).

### 7.2. AI Layer

- Расширить менеджер провайдеров:
  - несколько ключей,
  - выбор активного провайдера,
  - выбор модели,
  - учет токенов и стоимости.

### 7.3. UI Layer

- В панели чата: `ProviderQuickSwitcher`.
- Для предложений ИИ: `MutationPreviewCard`.
- Для экспорта: обновленный `ExportDialog` (PDF/MD/PNG).
- Для шаблонов: `TemplateDialog`.
- Для синхронизации: `SyncReviewDialog` с подтверждением каскадных изменений.

### 7.4. Storage

- Расширить сериализацию проекта:
  - `cross_tree_edges`,
  - `project_settings`,
  - `chat_metadata`,
  - `schema_version`.

## 9. Критерии приемки

Версия `0.0.5` считается принятой, если:

1. Работает синхронизация всех трех деревьев с подтверждением каскада.
2. Есть меж-деревья мосты, видимые и навигируемые.
3. Глобальный чат может безопасно изменять узлы через подтверждение.
4. Экспорт работает в `PDF`, `Markdown`, `PNG`.
5. Есть шаблоны проектов (создание и применение).
6. Есть переключение провайдера/модели в чате и показ токенов.
7. При выходе с изменениями есть корректный диалог сохранения.
8. Проект сохраняется/загружается без потери новых сущностей.

## 10. Риски и открытые вопросы

### Риски

- Сложность согласования каскадных изменений между тремя деревьями.
- Рост UI-сложности в чате при добавлении mutation preview.
- Возможные регрессии в производительности рендера при большом числе мостов.

### Открытые вопросы (требуют финального решения)

1. Формат хранения проекта: единый JSON или переход на SQLite.
2. Правила разрешения конфликтов, если чат и пользователь меняют один узел параллельно.
3. Минимальный набор полей для карточки меж-деревья моста.
4. Политика расчета стоимости токенов (локально по конфигу или через API провайдера).
5. Точное поведение автосохранения при длинных ИИ-операциях.
