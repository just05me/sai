## 1. Обоснование

### 1.1. Где мы сейчас

Прототип v0.0.3 реализует полный core-цикл продукта согласно концепции:

- **Холст:** dot grid, панорамирование (MMB/Space+LMB), зум под курсором
- **Узлы:** BoxNode с 4 состояниями, кастомизация карточки, snap-to-grid
- **Связи:** ортогональные линии Manhattan routing, стрелки, точки излома
- **ИИ:** BYOK с 4 провайдерами, Cursor-style чат, стриминг, брейншторм → граф
- **Данные:** сохранение/загрузка tree.json, автосохранение, backup
- **Экспорт:** Markdown-ТЗ с выбором узлов/деревьев, PNG
- **UX:** полные контекстные меню, hotkeys (Del/Ctrl+A/D/Z/Y), undo/redo, recent projects

### 1.2. Что не хватает до продукта

На основе анализа codebase v0.0.3:

| Область | Статус | Разрыв |
|---------|--------|--------|
| **Редактирование путей** | точки излома отображаются на hover, но drag не сохраняет позиции | Нет связи handle → engine.update_edge_path |
| **Визуализация статусов** | статус draft/review/done/deprecated хранится, но не визуализирован | Нет цветовой индикации на карточке |
| **Множественный выбор** | Ctrl+A работает, но нет rubber band | Нельзя выделить область мышью |
| **Поиск** | Нет | Нет Ctrl+F |
| **Типы узлов** | Типы перечислены, но нет иконок | Только текст |
| **Связи** | Подпись есть, но нет инлайн-редактирования | Double-click не редактирует |
| **Auto-layout** | Нет | Узлы расставляются только вручную |
| **Экспорт SVG** | PNG есть, SVG нет | Только растровый экспорт |

### 1.3. Цель v0.0.4

Замкнуть базовый UX-цикл: пользователь может не только создавать и чатиться, но и полноценно редактировать граф, искать, группировать и экспортировать в векторном формате. v0.0.4 делает прототип пригодным для реального использования соло-фаундерами и вайбкодерами.

## 3. Функциональные требования

### 3.1. Множественный выбор и групповые операции

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-01 | Rubber band selection: drag на пустом месте холста → прямоугольник выделения | MUST |
| F-02 | Групповое перемещение: двигать любой из выбранных узлов → все двигаются | MUST |
| F-03 | Групповое удаление: Delete с выбранными узлами удаляет все + их связи | MUST |
| F-04 | Групповое копирование: Ctrl+C копирует выбранные узлы, Ctrl+V вставляет со смещением | SHOULD |

**Детали F-01:**
- Нажать LMB на пустом месте (не на узле/связи) → начать рисовать прямоугольник
- Прямоугольник рисуется полупрозрачным Santi (#743354) с белой рамкой 1px
- Все узлы, пересекающие прямоугольник, переходят в Selected
- Edge selection: связи, у которых оба конца попадают в прямоугольник
- Отпускание LMB → завершение выделения, прямоугольник исчезает
- Сброс выделения: клик на пустом месте

**Детали F-02:**
- При групповом перемещении все выбранные узлы сохраняют взаимное расположение
- Snap-to-grid применяется к опорному узлу (под курсором), остальные сдвигаются на ту же delta
- Позиции обновляются через engine.update_node_position для каждого узла

**Детали F-03:**
- При Delete с выбранными узлами:
  1. Собрать все node_id выделенных узлов
  2. Собрать все edge_id, где source или target — среди выделенных
  3. Удалить связи → удалить узлы (через engine.remove_node)
  4. Один checkpoint на всю операцию (через engine._checkpoint до начала)

- Рамка узла окрашивается в цвет статуса

### 3.7. Авторасстановка узлов (Auto-layout)

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-40 | Кнопка «Авторасстановка» в контекстном меню холста или тулбаре | SHOULD |
| F-41 | Алгоритм: grid-layout по топологической сортировке (на основе связей) | SHOULD |
| F-42 | Сохранить checkpoint перед расстановкой → undo откатывает | SHOULD |

**Алгоритм (упрощённый):**
1. Найти root-узлы (нет входящих parent/dependency edges) — Y = 0
2. Для каждого root: BFS по outgoing edges → каждый уровень на следующий Y-ряд
3. Разместить на гриде: шаг X = 280, Y = 140
4. Если есть циклы — разорвать случайным образом

Текущая схема v2 НЕ требует изменений:
- `control_points` в Edge уже есть — теперь заполняется пользователем
- `status` в Node уже есть — теперь визуализируется
- `style.show_description/show_tags/show_ai_status` в Node уже есть

Никаких миграций данных не требуется.

### 7.2. Новые файлы в проекте

