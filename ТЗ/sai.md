## 0. Эволюция и финальные решения по противоречиям

Продукт прошёл два контура:

1. **Десктоп-прототип** (v0.0.1–v0.0.6, Python + PySide6) — локальный холст, JSON-проекты, BYOK, три дерева.
2. **Веб-продукт** (спека Sai Web → код `sai_0_0_5` → релиз 1.0 от 2026-07-04) — браузер, Postgres, self-host + cloud.

| Тема | Было | Стало (финал) |
|------|------|----------------|
| Платформа | Нативный десктоп, отказ от Electron/web | **Web-first.** Десктоп — исторический прототип, не целевой релиз |
| Главная цель | «Генератор ТЗ» | **Инструмент мышления и визуализации.** Экспорт ТЗ — ключевой результат, не единственная цель |
| Синхронизация деревьев | Автокаскад при любом изменении | **Только по кнопке**, с подтверждением. Обычно после проработки дерева «Функции» |
| Память чатов | 30 дней (v0.0.5) | **Бессрочно**, пока пользователь сам не удалит |
| Стоимость токенов в чате | Показывать в панели чата | **Только в Usage**, не поминутно в ленте |
| Режимы ИИ | Один режим | **`Агент` / `Вопросы`** |
| Инфраструктура 1.0 | Полный стек Redis / Hocuspocus / BullMQ / Stripe | **1.0 стартует на Postgres + ключ ИИ.** Redis/collab/очереди — следующие версии |
| Auth в 1.0 | Magic link + OAuth | **Локальный пользователь.** OAuth/magic-link — план 1.1+ |
| Лицензия | MIT (черновик Q&A) vs LGPL (репозиторий) | **LGPL**, как в коде и корневом README |

Краткий журнал версий постановки: `concept` → desktop 0.0.1…0.0.6 → `sai_web` 0.1 → `sai_web` 1.0 → Ship 1.0 (сужение скоупа) → фактический changelog 1.0.0.

## 1. Суть продукта

**Sai** — рабочая среда для структурированного мышления: человек описывает идею, общается с ИИ и собирает три связанных дерева знаний. Sai забирает аналитическую работу BSA / Product / Project / Team Lead на этапе «от идеи до структуры», но **не пишет код и не управляет людьми**.

Правильная формулировка позиционирования: **ИИ-кофаундер и архитектор**, а не «замена всей команды».

Ключевой цикл:

1. Пользователь описывает идею (текст / файл / URL / Quick Capture).
2. ИИ и человек вместе раскладывают идею на узлы и связи.
3. Работа идёт сразу в трёх деревьях: **Разработка / Функции / Бизнес**.
4. У каждого узла есть изолированный чат; глобальный чат видит весь проект.
5. ИИ может предлагать изменения графа — **никогда не применяет их без Accept**.
6. Результат выгружается (Markdown и другие форматы) или расшаривается.

Sai **не является**: IDE, Notion/Obsidian, Jira/Linear, универсальной доской Miro/Figma.

## 2. Аудитория

| Сегмент | Боль | Ценность Sai |
|---------|------|--------------|
| Соло-фаундеры | Нет BSA/PM, идея не доходит до структуры | От фразы до карты и ТЗ без найма |
| Вайбкодеры | Чистый лист, потеря фокуса | Визуальное дерево + чат по узлу |
| Малые команды 2–5 | Размытые требования | Общий канвас и три угла зрения |
| Консультанты / наставники | Нужно показать структуру клиенту | Ссылка view-only / embed |
| Self-host команды | Данные нельзя отдавать в чужое облако | Один Docker-образ на своей VPS |
| Open Source / техPM | Нет формального ТЗ | Документация из графа |

Платформы: сейчас браузер (desktop-first канвас). Mobile — read-only и комментарии в v1, редактирование позже. Исторический десктоп целился в Linux (Ubuntu), затем Windows/macOS.

## 3. Что считается готовым продуктом сейчас

### 3.1. Золотой путь 1.0

Посторонний человек без автора проходит:

**создал проект → накидал узлы на трёх деревьях → поговорил с ИИ по конкретному узлу → выгрузил Markdown.**

Запуск: одна команда, **Postgres + свой AI-ключ**. Redis, Hocuspocus, BullMQ, Stripe для старта не обязательны.

### 3.2. Что уже в коде 1.0 (changelog 2026-07-04)

- Три дерева на React Flow, чат по узлу, 5 персон ИИ
- Мутации: Expand, Refactor, Bridge Suggest, Idea Score, Propose Tree — через подтверждение
- Мульти-провайдер BYOK (OpenAI, Anthropic, OpenRouter, DeepSeek, Ollama, custom)
- Экспорт Markdown / PDF / TXT / JSON / Mermaid
- Self-host Compose: Postgres + pgvector, без Redis
- Локальный пользователь, command palette, Quick Capture, i18n RU/EN, тёмная тема

### 3.3. Известные пробелы 1.0 (не дыры постановки, а долг реализации)

- Синхронизация трёх деревьев — в 1.1
- Mind Map View — в 1.2
- Auth только локальный
- Нет полноценного CI и широкого тестового покрытия

Полный контур ниже — целевая спецификация продукта. Если пункт помечен как «после 1.0», он не блокирует текущий релиз.

## 4. Бизнес-логика и поставка

### 4.1. Два режима

Один образ, поведение от окружения:

```
SAI_MODE=cloud      # SaaS, Stripe, облачное хранение
SAI_MODE=selfhost   # без биллинга и жёстких лимитов
```

В 1.0 `selfhost` / локальный режим: лимиты и биллинг — no-op.

### 4.2. Планы (целевой SaaS, не блокер 1.0)

| Параметр | Free | Pro $12/мес | Team $29/мес | Self-Host Pro $49/мес |
|----------|------|-------------|--------------|------------------------|
| Проектов | 5 | ∞ | ∞ | ∞ |
| Узлов на проект | 100 | 1 000 | ∞ | ∞ |
| BYOK | да | да | да | да |
| Mind Map / Quick Capture | да | да | да | да |
| Idea Score, Personas, Hypotheses, Snapshots, Time Travel | — | да | да | да |
| Real-time коллаборация, Team AI Memory, SAML | — | — | да | да |

Принцип: **платить за супер-силы ИИ и коллаборацию, не за хранение и не за токены.** Наценка на токены запрещена. Экспорт доступен на любом плане. Данные после отмены подписки не удаляются автоматически (90 дней).

Limit Gate: 80% — баннер; 100% — read-only + inline upsell, без блокирующих popup.

### 4.3. Иерархия данных

```
Account
 └── Workspace (Personal | Team)
      ├── Members + роли: Owner / Admin / Editor / Commenter / Viewer
      ├── BYOK-ключи (AES-256-GCM)
      ├── API-токены
      └── Projects
           ├── Tree: Разработка
           ├── Tree: Функции
           ├── Tree: Бизнес
           ├── CrossTreeEdges
           ├── Chats (Node + Global)
           ├── Snapshots
           └── Templates
```

Вложенные проекты не поддерживаются. Импорт/экспорт проекта — обязателен (формат `.sai` с совместимостью desktop v0.0.4+ по базовым полям).

## 5. Логика продукта

### 5.1. Три дерева

Это не папки, а три ментальные модели одной идеи.

| Дерево | Хоткей | Зачем | Типовые узлы |
|--------|--------|-------|--------------|
| **Разработка** | `1` | Как строить | API, БД, сервисы, компоненты |
| **Функции** | `2` | Что делает продукт | Экраны, флоу, состояния |
| **Бизнес** | `3` | Зачем и кому | Сегменты, каналы, юнит-экономика |

Можно работать только в одном дереве. Деревья связаны **мостами** (`CrossTreeEdge`): пунктир, цвет источника, карточка «откуда → куда», клик ведёт к целевому узлу.

**Синхронизация:** кнопка «Синхронизировать» → диалог конфликтов и предложений → пользователь принимает/отклоняет точечно. Лимит каскада — 20 узлов за операцию. При конфликте старое сохраняется, новое входит только после подтверждения. Нужны индикатор статуса синка на дереве и подсветка затронутых узлов.

### 5.2. Узлы и связи

Обязательные поля: `название`, `описание`. Узел можно создать без описания — он **явно красный / неполный**, пока описание не заполнено. Перед экспортом — валидация обязательных полей.

Статусы (актуальные): `idea | in_progress | done | blocked`. Гибкие, без автомата переходов.

История узла: кто изменил (user / ai / import), когда, diff. Опционально: tags, assignee, origin, hypothesisStatus, healthScore, decisionLog.

Связи: `parent-child`, `depends-on`, `relates-to`, `bridge`. Подписи редактируются. На десктопе у узла было **4 активные точки коннекта** (и вход, и выход) — на вебе то же правило: handles со всех сторон, drag-from-handle как в n8n.

Типы узлов (наследие десктопа, сохраняем как опцию карточки): feature ⭐, module 📦, question ❓, task ☑️, milestone 🏁, technology ⚙️, actor 👤, action ➡️, decision 🔀, note 📝.

### 5.3. Два layout одного графа

Mind Map — **не вторая сущность**, а второй движок отрисовки тех же узлов.

- **Tree View** — структурное дерево (классический Sai)
- **Mind Map View** — Radial / Hierarchical / Force-directed / Free

Хоткей `M`. Данные не копируются. Генерация карты: идея, `.md/.pdf/.txt`, URL, голос (Whisper), или перекладка существующего проекта. Параметры: `max_depth` (3), `branching_factor` (4–6), язык workspace.

### 5.4. ИИ: режимы и мутации

| Режим | Поведение |
|-------|-----------|
| **Вопросы** | Только текст, граф не меняется |
| **Агент** | Может готовить мутации, каждая — на подтверждение |

Если узлов нет, ИИ — помощник, пока пользователь не создаст структуру (или не запустит Quick Capture / Propose Tree).

| Действие | Хоткей | Суть | Подтверждение |
|----------|--------|------|---------------|
| Expand | `E` | ≈4 дочерних узла | Accept all / selected / Skip |
| Deepen | `D` | Node Chat по ветке + decision log | Без авто-мутаций |
| Refactor | `R` | Разделить / слить / переименовать | Preview → Apply / Skip / Stop |
| Bridge Suggest | `B` | Мост в другие деревья | Accept / Dismiss |
| Score Node | — | Оценка описания | Replace / Append / Skip |

Базовый поток подтверждения — **пошаговый**; в конце можно пакетно дожать список. Карточка операции: тип `create/update/delete/link`, объект, diff. Кнопки: Применить / Пропустить / Остановить.

Персоны Global Chat (Pro+ в SaaS, в 1.0 уже есть в коде): Investor, Devil's Advocate, Customer, Architect, Mentor.

### 5.5. Чаты

| Чат | Контекст | Может |
|-----|----------|-------|
| **Node Chat** | Открытый узел + путь + соседи + decision log | Только этот узел (плюс явно прикреплённые) |
| **Global Chat** | Весь проект; drag узлов в чат | Создавать/менять/связывать узлы в режиме Агент |

Разрешено: переход к связанному узлу из чата, очистка, новый чат, экспорт истории. Streaming (SSE), кнопка Stop, частичный ответ сохраняется. Provider Quick Switcher в панели. Вложения: PDF / MD / TXT / изображения.

Хранение: **до явного удаления**. Стоимость и токены — в разделе **Usage**, не в каждом сообщении.

### 5.6. Quick Capture, Idea Score, гипотезы

**Quick Capture** — главный acquisition: `/capture` или «Попробовать» на лендинге, без регистрации, сессия 24 часа. Фраза ≤500 символов → за ≤15 с skeleton из 9 узлов (по 3 на дерево). Сохранение требует регистрации, данные сессии не теряются.

**Idea Score** (Pro+, после ≥30% заполнения): техническая реализуемость, рынок, полнота, слепые пятна. Экспорт PDF / PNG-карточка.

**Hypothesis Tracker:** `untested → testing → validated | invalidated`. Смена статуса требует заметки «что узнали» → `decisionLog` → дальше в контекст ИИ.

### 5.7. Шаблоны, метрики, надёжность

Шаблоны обязательны: структура + контент узлов, личные / workspace / публичные, импорт-экспорт `.sai-template`, форк и рейтинг.

Метрики на канвасе минимальны (число узлов и распределение). Отдельный экран **Usage**: токены, история, расход.

Автосохранение — включено по умолчанию и настраивается. Выход с dirty state — диалог Сохранить / Не сохранять / Отмена. Undo/Redo — глубокий, в пределах лимита. При порче файла — восстановление через логи/снапшоты. Ошибки — человеческим языком + Повторить / Открыть логи / Написать разработчику.

Режим **Редактор / Просмотр**: в просмотре граф и ИИ-мутации запрещены, навигация/поиск/экспорт работают.

## 7. UX и визуальный язык

Интерфейс = инженерная эстетика редактора кода (Cursor) + бесконечный холст (Figma/n8n), без корпоративного шума. Ориентир — **цифровой журналинг**, не стерильный клон VS Code.

### 7.1. Палитра

Фирменный акцент **Santi `#743354`**. База — Catppuccin.

**Тёмная (основная):** холст `#1e1e2e`, панели `#181825`, точки сетки `#313244`, текст `#cdd6f4`.

**Светлая:** холст `#f4f4f7`, панели `#ffffff`, точки `#e2e2e9`, текст `#4c4f69`, тот же Santi.

Шрифты: интерфейс Inter / SF Pro; контент узлов и чата — моно (`JetBrains Mono` / `Fira Code`). Радиусы: 8px карточки, 6px контролы.

### 7.2. Компоновка

Центр — холст. Справа — чат + свитчер `Агент/Вопросы` и провайдера. Слева — навигация/структура. Снизу — миникарта. Меню: File, Export, Templates, Usage, Settings.

Сайдбары **сжимают** холст, не перекрывают узлы. Focus Mode (`Ctrl+B` на десктопе, `F` на узле в вебе) оставляет только холст.

Сетка — **dot grid**, шаг 24px. Pan: Space или средняя кнопка, курсор «сжатая рука». Двойной клик по пустому холсту создаёт узел в координатах курсора.

Чат — плоская лента в стиле Cursor, без пузырей мессенджера. Заголовок динамический: «Контекст: [узел]». `@` — прикрепление узла.

### 7.3. Онбординг и состояния

Три шага: фраза идеи → skeleton 9 узлов (анимация ≤15 с) → интерактивный обход «нажми E». Сэмпл-проект нельзя удалить первые 24 часа.

AI-действия всегда имеют Loading / Success / Error. Ошибка конкретная: «ключ недействителен → обновить», «лимит провайдера → сменить», «провайдер недоступен → повторить». Никакого «что-то пошло не так».

Empty: пустой проект предлагает фразу; пустой поиск — «создать узел с таким именем?»; нет ключа — «настроить BYOK».

Key Setup Wizard: OpenAI, Anthropic, OpenRouter, Ollama (`localhost:11434` автодетект), кнопка «Проверить».

## 10. Безопасность

BYOK — **zero-knowledge сервера**: ключ шифруется в браузере (Web Crypto, AES-256-GCM, PBKDF2), в БД лежит BLOB, на сервере расшифровывается только в момент запроса, не логируется и не кешируется.

Обязательно: TLS 1.3, строгий CSP, CORS whitelist, Prisma-параметры против SQLi, DOMPurify/TipTap против XSS, SameSite cookies, Redis/in-app rate limit, секреты только из env, audit log чувствительных действий, ориентация на OWASP Top 10. Внешний pentest — перед широким публичным запуском cloud.

Базовое шифрование достаточно: проект открытый, пользовательские AI-ключи — главная тайна.

## 11. Offline, коллаборация, конфликты

- Service Worker + последний Yjs snapshot в IndexedDB (в 1.0 — заглушка SW).
- Offline-правки мержатся через Yjs; toast «N изменений синхронизировано».
- Tombstone UI, если проект удалили, пока клиент был offline.
- Два слоя: operational (Yjs BLOB) и structured (таблицы nodes/edges для API, поиска, экспорта). Sync structured — каждые 30 с или idle.

| Конфликт | Политика |
|----------|----------|
| Внутри дерева | Yjs merge (LWW + vector clock) |
| Cross-tree sync | Подтверждение человека, лимит 20 |
| Snapshot restore | Новая ветка, текущее не затирается |
| Offline | Автоmerge + toast |

Интерфейс отзывчивый: сеть и тяжёлое — асинхронно. Linux — главная платформа self-host. WCAG 2.1 AA, полная клавиатура, aria, `prefers-reduced-motion`. Языки: RU и EN.

Self-host: 4 CPU / 8 GB ≈ 100 MAU. Образы: `sai-app` ≤500 МБ, worker ≤300 МБ, pdf ~600 МБ (профиль). Обновление: `docker compose pull && up -d`, миграции при старте, CHANGELOG по semver.

Логи ошибок пригодны для восстановления; на десктопе держались локально до 96 часов — в вебе тот же принцип: рядом с данными, ротация.
