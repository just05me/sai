# Техническое задание (ТЗ) на разработку проекта «Sai»

## 1. Описание продукта

**Sai** — это десктопное приложение с открытым исходным кодом (Open Source), представляющее собой ИИ-кофаундера и архитектора проектов. Платформа предназначена для помощи разработчикам в проектировании программных продуктов: от генерации идей (brainstorm) до автоматического создания связанных функциональных деревьев и генерации финального технического задания. Продукт забирает на себя первичную аналитическую работу уровня BSA, Product/Project менеджеров и Team Lead-ов.

## 2. Целевая аудитория и Позиционирование

* **Аудитория:** Разработчики, соло-фаундеры, "вайбкодеры".
* **Подход к ИИ:** BYOK (Bring Your Own Key). Система работает исключительно через API внешних LLM, которые оплачивает и подключает сам пользователь.
* **Платформа:** Нативное десктопное приложение. MVP разрабатывается под **Linux (Ubuntu)**, с последующей упаковкой под Windows и macOS. Никаких веб-технологий (Electron/Tauri) в ядре.
* **Эстетика:** "Цифровой журналинг" (Scrapbook Aesthetic), минимализм, темная тема (ориентир на палитру Catppuccin). Отсутствие громоздких корпоративных UI-элементов.

## 3. Технологический стек (MVP)

* **Язык программирования:** Python 3.12+
* **GUI Фреймворк:** PySide6 (Qt for Python).
* **Рендеринг холста:** Инструменты `QGraphicsScene` + `QGraphicsView` для максимальной производительности 2D-графики.
* **Архитектурный паттерн:** Scene Graph + Signals/Slots (без использования веб-паттернов вроде Virtual DOM или React-подобного стейт-менеджмента). Работа в фоне через `QThreadPool` и `QRunnable`.
* **Хранение данных:** Локальная файловая система (`.json` и `.md`).

## 4. Архитектура и Структура данных

### 4.1. Типы деревьев (Графов)

Система состоит из трех взаимосвязанных структур. Изменение узла в одном дереве каскадно (через ИИ-триггеры) обновляет другие:

1. **Дерево функционала (Core):** Главное дерево. Определяет, *что* делает продукт. Пользователь и ИИ начинают работу с него.
2. **Дерево разработки:** Roadmap и Архитектура. Определяет, *как* продукт создается (технологии, базы данных, спринты).
3. **Дерево бизнес-логики (Предложение):** Пользовательский путь (User Journey) от старта до целевого действия.

### 4.2. Элементы графа

* **Бокс (Узел / Функция / Вопрос):** Содержит метаданные: Значение, Описание, Идентификатор сессии чата.
* **Стрелка (Путь / Ответ / Причина):** Соединяет боксы, имеет описание логики перехода.

### 4.3. Локальное хранение (File System)

Каждый проект представляет собой локальную директорию на диске пользователя:

* `[project_name]/tree.json` — содержит координаты `x, y` всех боксов, связи (edges), иерархию и базовые метаданные.
* `[project_name]/chats/` — директория с ИИ-памятью. Каждый диалог внутри конкретного бокса сохраняется в отдельный файл (например, `node_id.md`), где лежат контекст, описание и логи общения.

## 5. Основной функционал продукта

### 5.1. Бесконечный холст (Infinite Canvas)

* Отрисовка фоновой сетки (dot grid) без потери производительности.
* Интерактивность: Drag & Drop элементов, Pan (перемещение) и Zoom (масштабирование) камеры.
* Создание, удаление и редактирование боксов. Ручное и автоматическое соединение их гладкими кривыми Безье.

### 5.2. Интеграция ИИ и Изолированный контекст

* **Глобальный генератор:** Стартовый чат, где пользователь описывает идею. ИИ проводит браин-шторм и возвращает жестко структурированный JSON, на основе которого на холсте строится первичное Дерево функционала.
* **Изолированные чаты узлов:** При открытии "Бокса" стартует изолированная сессия. ИИ получает в контекст только информацию об этом конкретном боксе и его ближайших связях.
* **Наследование контекста:** Возможность сослаться на предыдущие чаты для продолжения логики.
* **API Подключение:** Настройки для ввода `API Key` и `Base URL` (для совместимости с DeepSeek API и другими OpenAI-совместимыми провайдерами).

### 5.3. Экспорт и Документация

* Парсинг готового Дерева функционала и Дерева разработки для автоматической генерации классического ТЗ (в формате Markdown) по запросу пользователя.

## 6. Требования к UI/UX

* **Трехпанельная компоновка окна:**
1. **Левый сайдбар:** Дерево файлов проекта / навигация.
2. **Центральная зона:** `QGraphicsView` с бесконечным холстом.
3. **Правый сайдбар (выезжающий `QDockWidget`):** Интерфейс общения с ИИ в контексте активного Бокса.


* **Стилизация (QSS):** Гладкий, "бесшовный" дизайн. Кастомные скроллбары, устранение стандартных рамок (`border: none`), минималистичные шрифты.

## 7. Этапы разработки MVP (Roadmap)

* **Stage 1: Базовое Окно.** Инициализация `QMainWindow`, настройка стилей QSS (темная тема), создание структуры проекта.
* **Stage 2: Движок Холста.** Настройка `QGraphicsScene`, панорамирования, зума, отрисовки сетки.
* **Stage 3: Узлы и Связи.** Разработка классов `BoxNode` и `EdgePath`. Реализация их перетаскивания и автоматической перерисовки соединительных линий.
* **Stage 4: Data Layer.** Подключение логики сохранения положения узлов и связей в локальный `tree.json` и их загрузки при старте приложения.
* **Stage 5: LLM Worker.** Создание асинхронного сервиса для отправки запросов к API. Написание системного промпта, который заставит LLM отдавать структуру дерева в JSON.
* **Stage 6: Context Chats.** Разработка UI правого сайдбара. Интеграция системы сохранения логов в папку `chats/` с привязкой к ID боксов.
* **Stage 7: Генератор ТЗ.** Модуль экспорта, который проходит по графу `tree.json` и формирует итоговый Markdown-документ.
