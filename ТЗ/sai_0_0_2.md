## 1. Описание продукта

**Sai** — нативное десктопное приложение с открытым исходным кодом (Open Source), реализующее концепцию **ИИ-кофаундера и архитектора проектов**.

Продукт автоматизирует первичную аналитическую работу, традиционно выполняемую BSA, Product/Project менеджерами и Team Lead-ами:

- Перевод абстрактной идеи в формализованную структуру (функциональное дерево)
- Декомпозиция функционала на модули, узлы и связи
- Построение Roadmap и архитектурного плана
- Генерация пользовательского пути (User Journey)
- Автоматическое составление полноценного технического задания (Markdown)

Sai не заменяет разработку кода — он заменяет этап **проектирования и аналитики**, делая его наглядным, связным и управляемым через ИИ.

### 1.1. Ключевая ценность

- **Соло-фаундеры** получают «продуктовый отдел в коробке» без найма BSA и PM
- **Вайбкодеры** перестают тонуть в хаосе идей и получают структуру
- **Команды** ускоряют этап предварительного анализа в 5–10 раз

## 2. Целевая аудитория и позиционирование

### 2.1. Аудитория

| Сегмент | Боль | Решение Sai |
|---------|------|-------------|
| Соло-фаундеры | Нет команды для аналитики, идеи остаются идеями | ИИ-архитектор, который ведет от идеи до ТЗ |
| Вайбкодеры | «Чистый лист», отсутствие структуры, потеря фокуса | Визуальное дерево + контекстные чаты по узлам |
| Малые команды (2–5 чел) | Нет BSA/PM, требования размыты | Декомпозиция и Roadmap автоматически |
| Open Source проекты | Нет формального ТЗ для контрибьюторов | Генерация документации из дерева |

### 2.2. Позиционирование

- **Платформа:** Нативное десктопное приложение
- **MVP-платформа:** Linux (Ubuntu 22.04+)
- **Целевые платформы после MVP:** Windows, macOS
- **ИИ-модель:** BYOK (Bring Your Own Key) — пользователь подключает свой API Key
- **Лицензия:** Open Source (LGPL / MIT — фиксируется отдельно)
- **Эстетика:** Цифровой журналинг (Scrapbook Aesthetic), темная тема, Catppuccin-палитра

### 2.3. Анти-позиционирование (что Sai НЕ является)

- ❌ Не IDE — не предназначен для написания кода
- ❌ Не Notion / Obsidian — не система заметок общего назначения
- ❌ Не Jira / Linear — не трекер задач для команды
- ❌ Не Miro / Figma — не универсальная доска для брейнштормов

## 3. Технологический стек

### 3.1. Базовый стек (MVP)

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| Язык | Python 3.12+ | Экосистема AI/ML, кроссплатформенность, читаемость |
| GUI | PySide6 (Qt for Python) | Официальные биндинги Qt6, LGPL-лицензия |
| 2D-движок | QGraphicsScene + QGraphicsView | Максимальная производительность для графов и канваса |
| Архитектура | Scene Graph + Signals/Slots | Никаких веб-паттернов, прямой контроль рендеринга |
| Асинхронность | QThreadPool + QRunnable | Фоновые запросы к API без блокировки UI |
| Стилизация | QSS (Qt Style Sheets) | Аналог CSS для нативного UI |

### 3.2. Зависимости (Python packages)

```
pyside6>=6.7.0           # Qt for Python
httpx>=0.27.0            # HTTP-клиент для API LLM (асинхронный)
pydantic>=2.0.0          # Валидация данных и схем JSON
orjson>=3.9.0            # Быстрый JSON (замена стандартному json)
markdown>=3.5.0          # Для экспорта в MD
```

### 3.3. Обоснование отказа от альтернатив

| Технология | Почему нет |
|-----------|------------|
| Electron / Tauri | Веб-технологии в ядре — лишний оверхед, не нативный опыт |
| PyQt6 | GPL-лицензия, проблемы с коммерциализацией |
| Pygame / Arcade | Не предназначены для UI с деревьями и чатами |
| SQLite (для MVP) | Оверинжиниринг для первой версии, JSON + Git — родной для разработчиков |
| React Flow / XYFlow | Веб-технологии, не работают в нативном Qt |

### 4.2. Паттерны и принципы

- **Scene Graph:** UI-компоненты на холсте — это не DOM-элементы, а QGraphicsItem с наследованием трансформаций от родителя
- **Signals/Slots:** Коммуникация между слоями через Qt-сигналы, а не колбэки или события
- **Repository:** FileStore реализует паттерн Repository, скрывая детали файлового I/O
- **Strategy:** LLM Service использует Strategy для поддержки разных провайдеров (OpenAI-compatible)

### 4.3. Поток данных (Data Flow)

```
Пользователь описывает идею в Global Chat
    → LLM Service → возвращает JSON-структуру дерева
    → GraphEngine импортирует узлы и связи
    → UI Layer отрисовывает на холсте

Пользователь кликает на узел (Box)
    → Right Panel открывает изолированный чат
    → ChatManager загружает контекст: этот узел + соседи
    → LLM Service получает контекст → ответ в чат

Пользователь редактирует узел
    → GraphEngine обновляет node
    → FileStore сохраняет tree.json
    → (опционально) LLM триггерит обновление связанных узлов
```

## 5. Структура данных

### 5.1. Формат проекта на диске

Каждый проект — отдельная директория:

```
my_project/
├── .sai                   # Метка, что это проект Sai (пустой файл-маркер)
├── tree.json              # Главный граф: узлы, связи, координаты, метаданные
└── chats/
    ├── global.md           # Стартовый/глобальный чат (брейншторм)
    ├── node_<uuid>.md      # Чат конкретного узла
    ├── node_<uuid>.md
    └── ...
```

### 5.2. Схема tree.json (v1)

```json
{
  "sai_version": "0.0.2",
  "project": {
    "name": "MyProject",
    "description": "Описание проекта",
    "created_at": "2026-05-23T10:00:00",
    "updated_at": "2026-05-23T12:00:00"
  },
  "trees": {
    "functional": {
      "label": "Дерево функционала",
      "description": "Что продукт делает",
      "nodes": {},
      "edges": []
    },
    "development": {
      "label": "Дерево разработки",
      "description": "Как продукт создается",
      "nodes": {},
      "edges": []
    },
    "business": {
      "label": "Дерево бизнес-логики",
      "description": "User Journey и бизнес-процессы",
      "nodes": {},
      "edges": []
    }
  },
  "view": {
    "offset_x": 0,

```

### 5.3. Схема узла (Node)

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "type": "feature",
  "label": "Авторизация через Telegram",
  "description": "Пользователь может войти через Telegram OAuth",
  "status": "draft",
  "position": { "x": 250.0, "y": 180.0 },
  "metadata": {
    "chat_id": "node_a1b2c3d4",
    "created_at": "2026-05-23T10:30:00",
    "updated_at": "2026-05-23T11:00:00",
    "generated_by": "ai",
    "ai_context_summary": "Краткое описание для повторной подачи в LLM"
  },
  "style": {
    "width": 200,
    "height": 80,
    "color": "#a6e3a1",
    "bg_color": "#313244"
  }
}
```

**Поля type:**

| Тип | Дерево | Описание |
|-----|--------|----------|
| `feature` | functional | Функция продукта |
| `module` | functional | Группа функций |
| `question` | functional | Вопрос / точка принятия решения |
| `task` | development | Конкретная задача разработки |
| `milestone` | development | Веха / спринт |
| `technology` | development | Технологическое решение |
| `actor` | business | Участник / роль |
| `action` | business | Действие пользователя |
| `decision` | business | Точка ветвления |
| `note` | any | Заметка / комментарий |

### 5.4. Схема связи (Edge)

```json
{
  "id": "edge_f7g8h9i0",
  "source_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "target_id": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
  "label": "Требуется для",
  "description": "Модуль оплаты требуется для завершения заказа",
  "edge_type": "dependency",
  "style": {
    "color": "#89b4fa",
    "width": 2,
    "line_style": "solid"
  }
}
```

**Поля edge_type:**

| Тип | Описание |
|-----|----------|
| `dependency` | Узел B зависит от узла A |
| `parent` | Иерархия: A содержит B |
| `sequence` | A происходит перед B |
| `alternative` | Альтернатива A или B |
| `refinement` | A уточняется через B |
| `trigger` | A вызывает/триггерит B |

## 8. Требования к UI/UX

### 8.1. Общая компоновка (Layout)

### 8.2. Панели

#### Левая панель (Project Explorer)

- **Тип:** `QDockWidget` (закрываемый, но не удаляемый по умолчанию)
- **Содержимое:** `QTreeView` + кастомная модель (QAbstractItemModel)
- **Показывает:** файлы проекта, категории узлов
- **Минимальная ширина:** 200px
- **Хедер:** имя проекта, кнопка «+» (новый узел)

#### Центральная панель (Infinite Canvas)

- **Тип:** `QGraphicsView` как centralWidget
- **Фон:** dot grid, цветовая схема Catppuccin Mocha:
  - Фон: `#1e1e2e`
  - Сетка (точки/линии): `#313244`
- **Поведение:**
  - Левая кнопка мыши — Drag (ScrollHandDrag)
  - Колесико — Zoom
  - Правый клик — контекстное меню (создать узел, вставить и т.д.)
- **Верхняя панелька (toolbar):**
  - Кнопки для переключения между 3 деревьями
  - Кнопка «Автораскладка»
  - Кнопка «Экспорт ТЗ»
  - Кнопка «+» (создать узел)

#### Правая панель (AI Chat)

- **Тип:** `QDockWidget` (выезжающий, может быть закрыт)
- **Ширина по умолчанию:** 350px
- **Содержимое:**
  - Хедер: название активного узла (или «Global Brainstorm»)
  - Область сообщений: QScrollArea с QTextBrowser
  - Поле ввода: QTextEdit (многострочный, Shift+Enter — новая строка, Enter — отправить)
  - Кнопка отправки (→)
  - Индикатор печатания ИИ (анимированные точки)
- **Поведение:**
  - При клике на узел — загружается чат этого узла
  - При клике на пустое место — глобальный чат

### 8.5. Кривые Безье для связей

Связи рисуются как кривые третьего порядка (cubic Bezier):

- Стартовая точка: правый порт исходного узла
- Конечная точка: левый порт целевого узла
- Контрольные точки: смещение по X на 50% расстояния между узлами
- Динамическое обновление при перемещении любого из узлов

### 9.1. Core: GraphEngine

**Файл:** `src/core/graph_engine.py`

**Назначение:** Центральный управляющий графом. Содержит все узлы и связи для всех трех деревьев.

**API:**

```python
class GraphEngine(QObject):
    # Signals
    node_added = Signal(str, str)
    node_removed = Signal(str, str)
    node_moved = Signal(str, float, float)
    edge_added = Signal(str)
    edge_removed = Signal(str)
    tree_switched = Signal(str)

    def add_node(self, node: Node) -> str
    def remove_node(self, node_id: str) -> bool
    def update_node(self, node_id: str, data: dict) -> bool
    def get_node(self, node_id: str) -> Node
    def get_nodes_by_tree(self, tree_name: str) -> list[Node]
    def add_edge(self, source_id: str, target_id: str, **props) -> str
    def remove_edge(self, edge_id: str) -> bool
    def get_connected_nodes(self, node_id: str) -> list[Node]
    def auto_layout(self, tree_name: str) -> bool
    def to_dict() -> dict
    def from_dict(data: dict)
```

class LLMService(QObject):

**Системный промпт для брейншторма:**

```
Ты — ИИ-архитектор проектов. Твоя задача: проанализировать идею пользователя и
вернуть структурированное функциональное дерево в формате JSON.

Правила:
1. Выдели 5-10 ключевых функций продукта.
2. Разбей каждую на подфункции (если применимо).
3. Определи зависимости между функциями.
4. Верни ТОЛЬКО JSON, никакого пояснительного текста.

Формат ответа:
{
  "nodes": [
    {
      "id": "uuid",
      "label": "Название функции",
      "description": "Описание",
      "type": "feature",
      "parent_id": null
    }
  ],
  "edges": [
    {
      "source_id": "uuid",
      "target_id": "uuid",
      "edge_type": "dependency",
      "label": "зависит от"
    }
  ]
}
```
